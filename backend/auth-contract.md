## 사용자 요청 #114 — 로컬 변경 및 공동 검토 필요

2026-11-04 새 사용자 요청으로 가입 인증 요구를 제거하고 이메일은 비밀번호 재설정에만 사용한다.
이 브랜치의 로컬 동작은 기존 정본의 가입 인증/재설정 미구현 절과 다르며, 변경 요구와 제안 DTO는
[작업 이슈 #114](https://github.com/bongjunpyo/Sunny/issues/114)에 먼저 기록했다.
정본을 자동 수정하거나 운영 계약 승인을 주장하지 않는다. #111의 Resend 결정과 #112의 화면 담당 분담도 팀장 공동 검토 대상이다.
현재 로컬 연결은 사용자 설정 Gmail SMTP를 사용하며 운영 활성화/배포는 하지 않는다.

### PR 준비 중 확인한 통합 경계

최신 main `9997caa` 기준으로 가입/로그인·재설정 단위 흐름은 검증했지만,
사진 API(#94)는 `emailVerified=false`인 회원을 `403 UPLOAD_SESSION_NOT_ELIGIBLE`로 거절한다.
따라서 가입 인증 제거 정책을 사진 권한 계약과 함께 합의하기 전에는 완성된 운영 가입 흐름으로
간주하거나 main에 반영하지 않는다. 사진 API/권한을 본 이슈에서 임의 완화하지 않았다.
최신 사용자 요청으로 PR 등록은 허용됐으며, 기존 미커밋 작업을 보존한 별도 브랜치
`feat/back-signup-password-reset`에서 Draft PR로 공동 검토한다. 실제 Gmail 수신은 미검증이다.

## 구현 근거

- Better Auth 고정 버전의 실제 모델과 `0002_authentication.sql`의 UUID·FK·권한·RLS를 대조한다. 적용 SQL을 수정하지 않는다.
- 인증 역할과 업무 역할의 pool을 분리하며 `pg_catalog` 우선 검색 경로를 유지한다.
- 재설정 메일 장애는 요청별 실패 여부만 추적한다. 가입·로그인은 메일과 독립이며, 재설정 발송 실패는 성공으로 바뀌지 않는다.
- scrypt와 기존 계정/secret/SQL은 유지한다. 가입 때 emailVerified를 허위로 true로 기록하지 않는다.
- 재설정은 Better Auth의 토큰 소비·비밀번호 갱신·세션 폐기 트랜잭션을 사용한다. 소셜 전용 계정의 credential 생성은 별도 경계로 거부한다.
- 게스트 재사용의 DB 세션 갱신 쿠키, native 요청 제한의 재시도 헤더, 명시적 경로/메서드 경계를 회귀 테스트한다.

## 검증과 남은 범위

실행 명령·환경변수·외부 설정의 원본은 [README.md](README.md)에 위임한다.

- `backend/auth/tests/`는 합성 계정·테스트 mailer·모의 카카오와 별도 PostgreSQL로 가입 무메일·로그인·재설정·게스트 보존·만료/폐기·쿠키·오류 격리를 확인한다.
- `smtp-mail.test.ts`는 모의 TLS SMTP 발송까지 연결한다. 실제 Gmail 수신/운영 배포 검증과 구분한다.
- 이전 `http-flow.mjs`는 가입 인증을 검사하던 도구이므로 현재 새 흐름 검증에는 사용하지 않는다.
- 서비스 자체 동의 증빙·공유 요청 제한·게스트 복구와 운영 수치 합의는 정본의 미완료 목록을 따른다.
- 테스트가 만든 합성 ID만 정리하고 기존 사용자/비밀번호/세션/사진·볼륨·인증 secret을 보존한다. 개인정보·인증 링크·원본 provider 오류를 PR/Git에 기록하지 않는다.
