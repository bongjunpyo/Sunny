# 인증 구현·검증 메모 — #90 / PR #92

인증 API·입력/표시 DTO·DB 세션/쿠키·Origin·오류·개발 정책의 정본은
[CONTRACT_API.md의 인증 절](../docs/CONTRACT_API.md#인증-계약--pr-92)이다.
PR #92에서 사용자 요청으로 검토안을 정본으로 옮겼으며 공동 리뷰 대상이다.
이 문서에 API 표·정책 수치를 중복 정의하지 않는다. 운영 승인/배포 완료를 뜻하지 않는다.

## 구현 근거

- Better Auth 고정 버전의 실제 모델과 `0002_authentication.sql`의 UUID·FK·권한·RLS를 대조한다. 적용 SQL을 수정하지 않는다.
- 인증 역할과 업무 역할의 pool을 분리하며 `pg_catalog` 우선 검색 경로를 유지한다.
- 메일 장애는 요청별 실패 여부만 추적한다. Better Auth 내부에서 예외를 흡수해도 가입 성공으로 바뀌지 않으며 동시 요청 간 상태를 공유하지 않는다.
- 게스트 재사용의 DB 세션 갱신 쿠키, native 요청 제한의 재시도 헤더, 명시적 경로/메서드 경계를 회귀 테스트한다.

## 검증과 남은 범위

실행 명령·환경변수·외부 설정의 원본은 [README.md](README.md)에 위임한다.

- `backend/auth/tests/`는 합성 계정·테스트 mailer·모의 카카오와 실제 로컬 PostgreSQL로 DB 모델/권한·이메일 인증 전후 로그인·게스트 보존·만료/폐기·쿠키·오류 격리를 확인한다.
- `http-flow.mjs`는 별도 Next 개발 서버의 HTTP 가입→이메일 링크→로그인→DB 세션→로그아웃을 확인하는 명시적 로컬 검증 도구다. 실제 Resend 수신/운영 DB 검증과 구분한다.
- 비밀번호 재설정·서비스 자체 동의 증빙·공유 요청 제한·게스트 복구와 운영 수치 합의는 정본의 미완료 목록을 따른다.
- 테스트가 만든 합성 ID만 정리하고 기존 사용자/비밀번호/세션/사진·볼륨·인증 secret을 보존한다. 개인정보·인증 링크·원본 provider 오류를 PR/Git에 기록하지 않는다.
