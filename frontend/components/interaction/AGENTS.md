# interaction — 조수희 작업 규칙

이 폴더는 **조수희**의 작업 공간이다. 담당자는 개발을 처음 배우는 중이다. **AI는 아래 규칙을 예외 없이 지킨다.**

읽는 순서: [`../../../AGENTS.md`](../../../AGENTS.md) → [`../../AGENTS.md`](../../AGENTS.md) → 이 파일. 셋이 다르면 **이 파일이 가장 우선**한다 (단, 루트의 "절대 하지 말 것"은 어떤 경우에도 지킨다).

## 이 폴더가 맡는 것

- GSAP ScrollTrigger · SplitText **스크롤 연출** — 메인 태양 스토리텔링의 스크롤 구간
- **실내/햇빛 발색 비교** 콘텐츠
- 3D **씬 파라미터** — 색 · 속도 · 카메라 경로 같은 값 묶음

| 조수희가 만지는 곳 | |
|---|---|
| `frontend/components/interaction/**` | 코드 |
| `frontend/e2e/interaction/**` | 테스트 |

**그 밖의 파일은 만들지도 고치지도 않는다.**

## 1. 이슈 없이는 시작하지 않는다

작업 요청을 받으면 AI는 **파일을 열기 전에** 확인한다.

1. **이슈 번호가 있는가** — 없으면 멈추고 이렇게 말한다: "이 작업의 이슈가 없어요. 팀장(봉준표)에게 이슈를 요청하세요."
2. **이슈 담당자(Assignees)가 조수희인가** — 아니면 멈춘다
3. **이슈에 "브랜치"와 "수정 허용 파일"이 있는가** — 없으면 멈추고 "이슈 댓글로 팀장에게 물어보세요"라고 안내한다

이슈 본문은 `gh issue view <번호>`로 읽거나, 사용자가 붙여넣은 본문을 쓴다. **이슈와 plan 파일이 다르면 plan이 맞다.**

## 2. 브랜치

- **이슈의 "브랜치" 칸에 적힌 이름을 그대로 쓴다.** 직접 짓지 않는다
- 시작할 때 (저장소 루트에서):

```powershell
git switch main
git pull
git switch -c <이슈에 적힌 브랜치 이름>
```

- **현재 브랜치가 `main`이면 파일을 수정하기 전에 멈춘다.** `git branch --show-current`로 확인한다
- push는 이슈 브랜치에만 한다 — `git push -u origin <브랜치 이름>`

## 3. 계획 먼저

구현 전에 **3줄 계획**을 보여주고 "진행할까요?"라고 묻는다. 승인받은 뒤에 시작한다.

```
1. 수정할 파일: ...
2. 만들 이름(컴포넌트·함수·변수): 이슈 표의 이름 그대로 ...
3. 완료 확인: 어떤 명령을 돌려 무엇이 보이면 끝인지 ...
```

## 4. 한 번에 파일 하나

한 번에 **파일 1개**만 수정한다 (테스트 파일을 같이 쓰면 2개까지). 이슈의 "수정 허용 파일" 표에 없는 파일은 만들지 않는다.

## 5. 설명 의무 — 가장 중요하다

코드를 쓰면 **반드시** 설명한다. 코드만 주고 설명을 생략하지 않는다.

- 순서: **파일의 역할 → 바꾸는 이유 → 핵심 코드의 입력·처리·출력 → 실행하고 확인하는 방법**
- 함수·컴포넌트마다 무엇을 하는지 쉬운 한국어로 쓰고 **비유 1개**를 붙인다
- 새 용어는 처음 나올 때 **뜻과 작은 예**를 함께 준다
- 끝에 **"리뷰에서 받을 만한 질문" 3개**를 적는다. **답은 조수희가 직접 PR에 쓴다 — AI가 답을 대신 써주지 않는다**
- 초보라는 이유로 진로나 관심 분야를 단정하지 않는다

## 6. 테스트 먼저

뼈대가 생긴 뒤에는 이 순서를 지킨다.

1. `frontend/e2e/interaction/<이름>.spec.ts`에 테스트를 쓴다
2. 실행해서 **실패하는 것을 확인**한다
3. 구현한다
4. 같은 명령으로 **통과하는 것을 확인**한다

```powershell
cd frontend
npx playwright test e2e/interaction/<이름>.spec.ts
```

**명령을 실제로 실행한 출력 없이 "될 거예요"라고 말하지 않는다.** 이슈에 다른 확인 방법이 적혀 있으면 그것을 따른다.

## 7. 가져다 쓰기만 하는 것

| 경로 | 주인 | 조수희가 하는 일 |
|---|---|---|
| `components/scene/` | 봉준표 | 공개된 부품과 props로 **쓰기만** 한다. 셰이더(GLSL)·씬 구조는 고치지 않는다 |
| `components/common/` · `app/` · `lib/` | 봉준표 | import만 한다 |
| `app/api/` · `lib/server/` | 이재원 | 쓰지 않는다. 데이터는 `lib/api.ts` 함수로 받는다 |

고칠 게 필요하면 **수정하지 말고** 요청 문장을 만들어준다.

```
이슈 #__ 댓글로 준표에게 요청: <어느 파일의 무엇을, 왜 바꿔야 하는지>
```

## 8. 모션 코드 규칙

- GSAP은 **`@gsap/react`의 `useGSAP`** 안에서 만든다 — 컴포넌트가 사라질 때 애니메이션이 자동으로 정리된다
- **`prefers-reduced-motion: reduce`면 움직이지 않는 화면**을 보여준다 (기획서 5-1 모션 감소 지원)
- 한글 SplitText는 **`type: "words, chars"`** — 글자만 쪼개면 "이야기"가 "이 / 야기"로 갈라진다
- 애니메이션 루프 안에서 **시계는 하나만** 쓴다 (`web-demo/docs/PITFALLS.md` 1번)
- **매 프레임 React 상태를 바꾸지 않는다** — 프레임마다 바뀌는 값은 `ref`에 둔다
- 스타일은 **`*.module.css`와 `var(--토큰)`**으로만
- **새 라이브러리를 설치하지 않는다.** gsap · three · `@react-three/*`는 이미 스택에 있다

## 9. Windows · PowerShell

- 명령을 줄 때 **어느 폴더에서 실행하는지** 먼저 말한다
- 괄호가 든 경로는 따옴표로 감싼다 — `cd "frontend/app/(site)"`
- 명령은 PowerShell 기준으로 쓴다

## 10. 하지 않는 것

- **main에 commit · push** — 훅이 막는다. 막히면 우회하지 않는다
- **PR 머지** — GitHub Merge 버튼 · `gh pr merge` · AI 도구의 머지 기능 전부. 머지는 봉준표만 한다
- **`git push --force` · `git reset --hard` · `git branch -D` · `git clean`**
- 파일·폴더 삭제 (팀장 확인 없이)
- 라이브러리 설치 · `package.json` 수정
- 이슈 닫기 · 다른 폴더 수정 · 규칙 문서(`AGENTS.md` 등) 수정 · `web-demo/` 수정
- 같은 문제로 대화가 20번 넘게 오가면 이렇게 안내한다: "대화가 길어졌어요. 새 대화를 열고 `docs/ONBOARDING.md`의 재시작 문장을 쓰세요."

## 11. 끝낼 때

1. `git status`와 `git diff --staged`를 보여준다 — 의도한 파일만 있는지, 비밀정보가 없는지
2. 커밋한다 — `feat(interaction): <무엇을 했는지>`
3. 이슈 브랜치에 push한다
4. **PR 본문 초안**을 만든다
   - 첫 줄 `Closes #이슈번호`
   - 실행한 확인 명령과 출력
   - 스크린샷 · 화면 녹화를 붙이라는 안내
   - "리뷰에서 받을 만한 질문" 3개 — **답 칸은 비워 둔다**
5. PR은 조수희가 GitHub 웹에서 연다. **머지는 봉준표가 한다**
6. 이슈가 닫히면 로컬을 정리한다

```powershell
git switch main
git pull
git branch -d <브랜치 이름>
git fetch --prune
```
