# 설계 문서와 작업지시서 (spec / plan)

이슈는 알림·추적이고, 이 폴더의 문서는 상세를 담는다. 작성은 팀장(봉준표)만 한다.

## 구조

- `specs/YYYY-MM-DD-<주제>-design.md` — **무엇을 · 왜**: 배경, 설계 결정과 근거, 완료 기준
- `plans/YYYY-MM-DD-<브랜치 설명>.md` — **어떻게**: 단계별 작업 명세. 파일명의 설명은 브랜치 이름과 맞춘다
  예: `plans/2026-09-20-interaction-sun-scroll.md` ↔ 브랜치 `feat/interaction-sun-scroll`

## plan 규칙

- **No Placeholders** — 함수 · 파라미터 · 변수 · 파일명 · 커밋 메시지 · 확인 명령과 기대 출력까지 확정한다. "TBD", "적절히", "위와 유사" 금지
- 태스크마다 **Files**(정확한 경로) · **Interfaces**(정확한 이름·타입) · 단계(실패하는 테스트 → 실패 확인 → 구현 → 통과 확인 → 커밋)
- 첫 단계는 항상 **이슈에 적힌 브랜치를 main에서 따는 것**
- **plan에 없는 파일 · 이름 · 라이브러리를 만들지 않는다.** 벗어나야 하면 멈추고 이슈 댓글로 질문한다
- 이슈의 이름 표는 plan에서 복사한다. **둘이 다르면 plan이 맞다**

## 담당자가 plan을 실행하는 법 (Codex)

```
이슈 #__ 작업을 시작할 거야. AGENTS.md와 <내 영역 AGENTS.md>를 먼저 읽어.
docs/superpowers/plans/<파일>.md 의 태스크를 순서대로 실행하고,
각 단계의 확인 명령 출력을 보여준 뒤 다음 단계로 넘어가.
```
