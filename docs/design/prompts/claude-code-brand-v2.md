# SUNNY — Claude Code용 개발·설계 프롬프트

너는 SUNNY 캡스톤 프로젝트의 시니어 프런트엔드 엔지니어이자 인터랙션 설계자다. 기존 저장소에서 작업하며, 새 프로젝트로 갈아엎지 않는다. 대답과 주석, 인수인계는 한국어로 작성한다.

## 0. 이번 작업의 범위와 안전장치
- 저장소: https://github.com/bongjunpyo/Sunny
- 먼저 로컬 git status, 현재 브랜치, CLAUDE.md, AGENTS.md, 담당 폴더 규칙, frontend/README.md, backend/README.md, package.json, lockfile, 기존 기획·API 계약을 읽는다. 존재하지 않는 경로는 만들거나 읽었다고 하지 말고 실제 위치를 찾는다.
- 변경 중인 파일을 덮어쓰지 않는다. main 직접 push, force push, reset --hard, 임의 merge, 규칙·훅 해제, 비밀정보 커밋을 하지 않는다.
- 저장소의 이슈·승인 절차를 따른다. 필요한 이슈 번호나 담당 범위가 없으면 읽기 전용 조사와 계획까지만 하고 요청한다.
- 기존 Next.js, Sanity, Supabase, Vercel 관련 설정이 실제로 존재하는지 먼저 확인한다. 새 FastAPI 서버, 새 데이터베이스, 새 프레임워크를 임의 도입하지 않는다.
- 이번 첫 실행의 산출물은 조사 결과, 파일 변경 계획, 수용 기준이다. 승인 전 기능 구현은 시작하지 않는다. 승인 후 아래 단계를 작은 단위로 구현한다.

## 1. 확정된 경험 방향
SUNNY는 팔찌 단일 제품 소개가 아니라 팔찌와 목걸이를 함께 전개하는 브랜드다. 브랜드의 출발점은 ‘태양과 교감한다’이며 태양은 브랜드의 상징이다. 첫 화면에서 브랜드 이름과 정체성이 먼저 인식되어야 한다. 제품은 히어로에 떠다니는 장식으로 넣지 않는다. 첨부 시안 main-hero-candidates.html의 A안, 즉 옆에서 들어온 태양이 가운데를 차지하고 정면으로 확대되어 태양 속으로 들어가는 구성을 선택한다. 시안 파일에 D안 선택 문구가 남아 있더라도 이번 요구는 A안이다. 기존 후보 데모는 보존한다.

이후 같은 페이지의 스토리보드로 자연스럽게 연결한다. 별도 라우트가 기존 기획에 명시돼 있으면 충돌을 보고한다. 기본값은 페이지 이동 없는 연속 스크롤이다.

핵심 원칙: 감성 연출 영역, 실제 관측 영역, 제품 영역을 구분한다. AI 영상을 NASA 실제 관측처럼 표시하지 않는다. NASA 자료가 제품 효능을 입증한다고 주장하지 않는다.

## 2. 브랜드 중심 페이지 정보 구조
1. Hero: SUNNY 워드마크 / 제안 카피 ‘빛을 지니는 방식.’ / 절제된 태양 / 컬렉션 바로가기. 카피는 승인 전 확정 문구로 취급하지 않는다.
2. A안: 측면 등장 → 중앙 정렬 → 정면 확대. 게임의 낙하·포털 대신 매끄러운 광량 변화로 브랜드 이야기로 이어진다.
3. Brand Story: 태양과 빛을 왜 몸에 지니는 형태로 해석하는지 짧은 문장과 큰 이미지로 전달한다. 발색 기능 설명 페이지로 만들지 않는다.
4. Collections: Bracelets와 Necklaces를 동등한 제품군으로 제시한다. 실제 상품이 없으면 기획 중이라고 표시하고 판매 중인 상품·가격·소재를 지어내지 않는다.
5. Editorial: 착용 장면, 빛과 피부, 실제 소재의 클로즈업. 실제 제품 사진과 분위기용 생성 이미지를 구분한다.
6. Solar Journal: NASA 실제 관측은 브랜드 영감의 기록으로 보조 배치한다. 메인에는 1장과 짧은 기록, 출처를 보여 주고 파장 탐색은 상세에서 제공한다. 천문학 대시보드가 홈페이지를 지배하지 않는다.
7. Footer: 브랜드 소개, 컬렉션 링크, 연락처 및 출처. 없는 구매·회원 기능을 작동하는 것처럼 꾸미지 않는다.

내비게이션 제안: SUNNY / Collections / Our Story / Solar Journal. 모바일에서도 컬렉션은 인트로 완료 없이 접근 가능해야 한다.
상품 모델은 bracelet과 necklace를 분리할 수 있는 category를 둔다. 기존 스키마를 조사하고 승인 후 확장한다. bracelet 전용 컴포넌트·URL·설명문을 공용 브랜드 기능에 하드코딩하지 않는다.
소재, 가격대, 타깃 성별, 발색 원리, 건강 효과, 지속가능성·수공예 여부는 확인 없이 설정하지 않는다.

## 3. 디자인 방향
- 목표는 성숙한 컨템포러리 주얼리 브랜드의 에디토리얼 웹이다. 비싼 소재나 럭셔리 가격대를 주장하라는 뜻이 아니다.
- 귀여운 태양 캐릭터, 미소 얼굴, 이모지, 통통한 아이콘, 젤리 버튼, 바운스, 과도한 둥근 카드, 장난감 같은 3D 비즈, 무지개 발색 효과를 금지한다.
- 검정+금색만으로 고급스러움을 대신하지 않는다. 금빛은 태양 이미지에 절제해 사용하고 UI는 차콜·오프화이트 중심으로 구성한다. 금박 테두리와 장식적 세리프 남용 금지.
- 주얼리 편집 화보처럼 큰 이미지, 정렬, 여백, 사진의 소재 디테일로 완성도를 만든다. 섹션마다 다른 효과를 추가하지 않는다.
- ‘태양과 놀아보세요’, ‘신기한 마법’, ‘나만의 반짝임’ 같은 귀여운 설명조 카피를 피한다. 영어를 장식처럼 남발하지 않는다.
- 모션을 꺼도 브랜드 페이지로 완성되어 보여야 한다. 첫 화면에서 SUNNY가 브랜드임을, 컬렉션에서 팔찌·목걸리를 함께 전개함을 인식할 수 있어야 한다.
- 배경: near-black #08090B, 본문 #F4F0E8, 보조색 #B6AEA2, 강조 amber #F3A33C. 이 팔레트는 제안이며 실제 대비 검사 후 조정한다.
- 도입부는 검은 우주와 거대한 태양, 스토리 구간은 warm ivory로 전환한다.
- 일반적인 SaaS 카드 그리드, 무분별한 glassmorphism, 네온 보라, 별 파티클 과다, HUD 장식, 폭발 영화 느낌은 피한다.
- 제목은 큰 에디토리얼 타이포, 본문은 읽기 쉬운 한국어 글꼴. 글꼴 라이선스를 확인하고 가급적 자체 호스팅한다.
- 화면에는 한 시점에 한 메시지만 강조한다. 텍스트를 이미지·영상에 굽지 않는다.
- 데스크톱에 넓은 여백, 모바일에 안전 영역과 충분한 글자 크기. hover 없이는 못 쓰는 기능 금지.

## 4. 스크롤 연출 사양
하나의 heroProgress(0~1)만 진실의 원천으로 사용한다. 아래 구간은 시간 아닌 스크롤 진행률이다.
- 0.00~0.18: 태양 중심을 화면 너비 약 110%에서 75%로 이동. 제목은 왼쪽. 처음에도 태양의 가장자리가 보이도록 실제 이미지 반지름 기준 검증.
- 0.18~0.38: 태양 중심을 50%로 정렬. 제목을 점진적으로 사라지게 한다.
- 0.38~0.72: 중심을 고정한 채 확대. 회전·롤·궤도 이동 없이 정면으로 진입한다.
- 0.72~0.88: 플라스마 근접 소스와 밝은 amber 레이어를 연결한다. 반복 섬광 없이 한 번의 부드러운 밝기 전환.
- 0.88~1.00: warm ivory의 브랜드 에디토리얼 스토리가 드러난다. pin 해제 시 레이아웃 점프가 없어야 한다.

PC hero 스크롤 길이는 240~320svh 범위에서 시작하고 모바일은 140~200svh로 축소 검토한다. 이 숫자는 튜닝 초기값이며 사용자 테스트 후 확정한다. 역스크롤, 중간 새로고침, resize, 터치 관성에서도 동일한 장면 상태를 복원한다.

MVP는 2D 이미지/비디오 레이어 + transform/opacity + 기존 애니메이션 도구로 구현한다. GSAP ScrollTrigger가 없으면 도입 필요성과 대안을 먼저 제시한다. Three.js는 실제 깊이·셰이더가 필요할 때만 추가한다. NASA 전면 원반 JPG를 구면 전체 텍스처로 감아 실제 3D 태양이라고 표현하지 않는다.

## 5. AI 에셋과 웹 코드의 역할 분리
- Higgsfield: 고정 카메라 태양 원반 영상 또는 포스터, 플라스마 표면 근접 이미지·영상.
- 웹 코드: 태양의 x 이동, scale, 텍스트, pin, 밝기, 스토리 진입.
- ‘전체 A안을 담은 긴 영상’에 모든 인터랙션을 의존하지 않는다.
- AI 영상에 이미 강한 카메라 이동이 있으면 코드 이동과 중복되지 않게 별도 cinematic 모드로 격리한다.
- 초기에는 포스터만으로 완전한 경험을 만든다. 영상이 없어도 레이아웃과 CTA가 동작한다.
- 영상 사용 시 muted, playsInline, poster, error fallback, 화면 밖 pause, 문서 hidden pause. 자동재생 거부는 정상 상태로 처리한다.
- 매 scroll event마다 video.currentTime을 무제한 변경하지 않는다. 스크러빙이 필요하면 seeking 상태·프레임 스케줄·키프레임 인코딩을 검증하고 별도 실험으로 수행한다.

## 6. NASA 실제 관측 통합
공식 자료:
https://sdo.gsfc.nasa.gov/data/
https://sdo.gsfc.nasa.gov/data/aiahmi/
https://sdo.gsfc.nasa.gov/data/channels.php
https://sdo.gsfc.nasa.gov/data/rules.php
https://api.helioviewer.org/docs/v2/

공식 페이지에서 확인된 최신 1024px JPG 주소:
171: https://sdo.gsfc.nasa.gov/assets/img/latest/latest_1024_0171.jpg
304: https://sdo.gsfc.nasa.gov/assets/img/latest/latest_1024_0304.jpg
193: https://sdo.gsfc.nasa.gov/assets/img/latest/latest_1024_0193.jpg

위 주소의 실제 이미지 응답, 콘텐츠 유형, 리다이렉트, CORS, 갱신 방식, 이용 조건을 구현 시 재검증한다. 주소가 존재한다는 사실만으로 현재 이미지의 관측 시각이나 실시간성을 단정하지 않는다. 직접 img 표시 가능 여부와 canvas/WebGL 픽셀 접근 가능 여부는 별개로 시험한다.

권장 MVP:
- 서버 측 고정 허용 목록을 통해 171/304/193만 취급한다. 사용자 임의 URL 프록시 금지.
- NASA API 키를 불필요하게 요구하지 않는다. 이 JPG 제공과 다른 NASA API를 혼동하지 않는다.
- 30~60분 주기 캐시는 우리 서비스의 권장 설정이며 NASA 갱신 보장이 아니다.
- 관측 이미지와 그 이미지에 대응하는 관측 시각을 한 묶음으로 저장한다. Helioviewer 시각을 별도 SDO latest JPG에 붙이는 식의 메타데이터 혼합 금지.
- 이미지의 검증된 메타데이터 또는 공식 아카이브 식별자로 관측 시각을 확인하지 못하면 observedAt은 null이다. fetchedAt을 관측 시각으로 사용하지 않는다. HTTP Last-Modified도 관측 시각으로 자동 해석하지 않는다.
- 타임아웃 8초, 제한된 재시도, 정상 이미지의 형식·크기 검사, last-known-good fallback을 설계한다. 서버리스 메모리나 임시 파일이 영속 캐시라고 가정하지 않는다. 기존 저장소·스토리지 사용 가능성을 먼저 확인한다.
- 실패 시 마지막 정상 관측 시각과 ‘이전 관측 이미지’를 표시한다. 정상 캐시도 없으면 ‘관측 이미지를 불러오지 못했습니다’와 공식 사이트 링크를 보여 준다. AI 이미지를 대체 관측으로 보여 주지 않는다.
- latest 주소는 내용이 바뀌므로 저장용 영구 식별자로 사용하지 않는다. 저장 스냅샷은 UTC 관측 시각 또는 수집 시각+해시로 식별하며 어떤 시각인지 명확히 구분한다.

제안 내부 API 계약(외부 NASA API가 아님):
GET /api/solar/latest?channel=171
{
  provider: 'NASA/SDO', instrument: 'AIA', channel: '171',
  imageUrl: '검증된 제공 이미지 URL', observedAt: null,
  fetchedAt: 'UTC ISO 문자열', observationTimeVerified: false,
  status: 'available | cached | unavailable',
  sourcePage: 'https://sdo.gsfc.nasa.gov/data/',
  attribution: 'Courtesy of NASA/SDO and the AIA, EVE, and HMI science teams.'
}
실제 구현에서는 위 유니온 표기를 문자열 리터럴 타입으로 구현한다. unavailable이면 imageUrl=null을 허용한다. 응답 계약은 기존 팀 계약과 합의 후 반영한다.

관측 카드:
- 제목 ‘최근 관측된 태양’(당일 관측을 검증한 경우만 ‘오늘의 태양’)
- NASA/SDO · AIA 171 Å
- 관측: 검증된 UTC 시각 / 한국 시간 변환. 미확인이면 ‘관측 시각 확인 불가’
- 수집: fetchedAt. 관측 시각과 별도 표기
- ‘파장별 관측을 색으로 표현한 이미지이며 육안으로 보이는 색과 다릅니다.’
- 공식 원본 보기 / 출처 문구
- 171=코로나 구조, 304=채층·전이영역, 193=코로나·뜨거운 플레어 플라스마라는 공식 설명을 간결하게 전달한다. 이미지 밝기를 UV 지수·안전도·제품 발색 수치로 환산하지 않는다.

Helioviewer API는 날짜 검색·동일 관측 ID와 시각 확보가 필요해지는 2차 단계에서 검토한다. 문서를 먼저 확인하고 sourceId와 엔드포인트를 추측하지 않는다.

## 7. 접근성·성능·에러 처리
- prefers-reduced-motion이면 pin dive·자동 영상·입자 효과를 해제하고 정적 태양 → 스토리 순으로 표시한다.
- 정상 모드도 ‘이야기로 바로 가기’를 항상 키보드 접근 가능하게 한다.
- 키보드 focus 표시, 탭 이름·선택 상태, 의미 있는 heading, 이미지 대체 텍스트를 제공한다.
- 마우스/휠을 강제 가로채지 않는다. pin 중 focus가 보이지 않는 위치로 이동하지 않게 한다.
- 360×800, 390×844, 768×1024, 1440×900에서 검사. iOS Safari와 Android Chrome은 실제 검증 여부를 구분한다.
- 무거운 리소스 lazy-load, 모바일 저해상도 에셋, 이미지 크기 예약, CSS transform 우선, RAF 정리, 이벤트·타임라인 dispose.
- 목표: LCP 2.5초 이하, CLS 0.1 이하, INP 200ms 이하. 목표이지 측정 결과가 아니다. 환경·측정 도구를 함께 보고한다. 실사용 INP와 실험실 추정치를 혼동하지 않는다.
- 영상 제외 초기 전송량 1.5MB 이하, 모바일 영상 3MB 전후, PC 영상 6MB 전후를 초기 예산으로 두고 실측 후 화질과 절충한다.

## 8. 단계별 산출물과 수용 기준
1단계 조사: 실제 파일 경로, 스택, 충돌, 작업 범위, 승인 필요 항목, 에셋 목록.
2단계 정적 뼈대: AI 파일 없이 A안→스토리→관측 카드→CTA가 동작.
3단계 모션: 진행률 기반 전환과 reduced-motion 대체가 동작.
4단계 데이터: 관측 카드 실제 연결, 출처, null 시각, 장애·캐시 처리.
5단계 에셋: 승인된 Higgsfield 소스 교체와 압축, 모바일 분기.
6단계 검증: lint/typecheck/build/기존 테스트. 테스트 도구가 없으면 실행 불가를 보고하고 도입 승인을 요청.

테스트 항목: NASA timeout/404/이미지 아닌 응답, observedAt null, 오래된 캐시, KST 날짜 경계, 파장 빠른 전환 요청 경쟁, 영상 autoplay 거부, reduced-motion, 역스크롤, resize, 새로고침, 키보드 skip, 이미지 누락.

최종 보고: 변경 파일별 이유, 실제 실행 명령·결과, 테스트하지 못한 항목, 교체할 에셋, 팀원 인수인계. 검증 없이 ‘완벽히 동작’이라고 하지 않는다.

지금은 1단계만 수행하고 구현 계획과 승인 질문을 제시해라.
